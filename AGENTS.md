# Repository contract

Preserve existing work and use scoped commits. After the initial repository bootstrap, work on a task branch, submit to develop, then promote develop to main through a separate PR. Main is the released branch. Do not force-push or rewrite legitimate history.

PLEGA uses an original paper-workshop interface, English/Spanish content and light/dark themes. The current user's explicit design and public GitHub Pages instructions govern this project. Runtime has no accounts, credentials, paid services or backend. Use original layouts and original or explicitly licensed project designs.

Keep frontend, original source data, deterministic processing, derived artifacts, tests, guides and delivery scripts separate. Product-specific TypeScript modules and Python scripts are sufficient; do not create an installable internal package or invent training methods.

Use millimetres consistently. The documented restricted geometry is authoritative. Renderer changes must not change physical coordinates, cut/fold assignments, closure checks or print scale. Distinguish unsupported geometry, a failed closed fit and uncertified lane overlap. Do not claim physical assembly validation from software tests.

Validate release artifacts from a clean exact revision. Test core invariants independently, check exported dimensions, and exercise the actual built app before publication. Secrets and private operator information must never enter source, public artifacts or logs.
